# 执行效率、证据复用与结构迁移

审查多批修改、重命名或迁移目录，或出现反复验证与耗时异常时读取。减少的是重复准备、漏检返工和重复解释，不能削弱已确定的检查与验收。

## 从当前阶段继续

复用任务的仓库、平台入口、工具能力、授权范围、已读指令与下一动作。只有版本、指令或能力变化时补读相关部分；跨上下文恢复先读简短状态与必要证据，复用仍适用的审查上下文。

连接器已满足操作时，不探测或安装另一个 CLI。调用前按当前工具描述核对参数；缺少某一能力时只补该能力。文件检索限定目录/类型，长日志先提取摘要、失败位置和计数，不向上下文倾倒完整日志、依赖目录或秘密。

正例：已有连接器能读取 PR 和 CI，就复用它；缺少 push 事件查询时只补相应只读入口。
反例：每次恢复都重读全部参考、枚举全部工具或重新检查所有平台 CLI。

## 结构迁移先核清执行入口

目录、模块、资源或测试发现路径变化时，建立简短的旧位置 → 新位置 → 消费方 → 验证入口映射，区分迁移、保留与薄兼容入口。核对当前 Git 跟踪材料，历史档案保留原始时间与含义。

| 入口类别 | 必查事项 | 对应验证 |
|---|---|---|
| 源码依赖 | import、动态模块名、相对资源根 | 实际安装/加载、相关调用方 |
| 命令与进程 | CLI、后台任务、子进程、管理与验收脚本 | 原样命令；必要时从仓库外目录运行 |
| 测试与 CI | 发现目录、注册列表、CI 路径 | 确认实际执行数量非零；不能只看退出码 |
| 构建与交付 | 包发现、模块清单、资源复制、保护/打包选择 | 最终产物中实际内容与启动消费 |
| 部署与配置 | 宿主路径、容器路径、配置消费方 | 脱敏夹具解析；必要的真实运行验证 |
| 当前文档 | 链接、代码块、表格里的命令和前置条件 | 链接存在与命令可运行分别检查 |

先搜索本次影响内同类引用，一次处理全部已确认实例。不能把“链接仍存在”当成“命令执行有效”，也不能把旧测试目录机械改成另一个无断言的目录。

正例：测试搬到组件目录后，同时修正发现器、CI 和 README 命令，运行文档中的命令并记录数量。
反例：第一轮改源码 import，第二轮才发现构建清单，第三轮又发现 README 运行零项；每轮仅修被点名的一行。

## 先说明哪些证据失效

每次返修先列出：改了什么 → 哪些检查输入改变 → 必须重跑什么 → 哪些原证据仍成立。依据实际调用/输入关系判断，不单靠文件后缀或改动行数。

| 实际变化 | 优先补验证 | 可复用条件 |
|---|---|---|
| 解释文字或文档命令 | 链接、原样命令、声明的前置条件 | 产品/构建输入未变，可复用已有运行证明 |
| 生产逻辑、状态或协议 | 相关正常/失败/并发用例，再按项目规则跑回归 | 未受影响的独立组件证据仍可保留 |
| 构建、部署或资源输入 | 产物内容、配置消费和受影响启动链路 | 不能只因业务源码未变就沿用旧产物 |
| 仅增加合并提交且树相同 | 核对组合、目标基线及必需合并检查 | 不重建相同镜像；平台要求的 CI 仍必须满足 |

项目既定本地与 CI 检查照常执行。独立审查者可核对作者的确切版本证据，另运行关键针对性探针；无新风险时不为证明独立而复制完整回归。失败先定位，保留原结果；偶发用例可单独复查，但不能覆盖失败记录或宣称未跑的全量通过。

正例：只修文档命令时，执行命令并核对新 CI，保留输入未变的已验证镜像。
反例：每个讨论回合都重建同一镜像、再跑全部测试，或因为本地通过就省略必需 CI。

## 并行与耗时归因

本地必需检查按项目安排执行。CI 与独立 AI 审查通常并行；任一失败由 Agent 处理，两者对当前版本通过后才进入最终人审。不为等待 CI 完成而让无依赖的材料准备停下。

在阶段开始/结束或关键工具返回时记录时间、责任人、版本和结果链接。区分执行、排队、等待业务决定、解释问答和现场结果；这些类别可能重叠，不能把各运行时长相加成墙钟耗时。缺少细分计时就标明区间与不确定性，不推算未经测量的节省百分比。

某步骤明显超出本项目已观察到的正常范围时，说明卡在代码、依赖、排队还是编排，继续可独立工作；不要无依据地保证固定分钟内完成，也不要把普通技术排障交给用户。

正例：报告 CI 的创建至结束区间，同时说明多个 PR 的 CI 有重叠；单列用户决策与说明材料耗时。
反例：声称总共三小时都在跑测试，或把流程说明不清导致的反复追问全部归为用户等待。
