# 审查场景验证

| 场景 | 应看到的行为 |
| --- | --- |
| 用户只说「做下 code review」 | 自动定位仓库，先读适用规则，确定版本与基线，交付审查结果。 |
| 根 CLAUDE.md 和 REVIEW.md 都缺失 | 调查现有资料，调用内置方法给完整草案并请用户确认；确认前不写入，独立审查继续。 |
| 只缺 REVIEW.md，已有等价 AGENTS.md | 保留已有规则，只为缺失文件起草，引用已有事实而不重复另一套要求。 |
| 起草规则时缺少架构或业务依据 | 从真实入口整理模块、接口与状态归属；未知项标待确认并问必要问题，不编造实现或命令。 |
| 用户认可规则草案，但尚未审核产品变更 | 仅按确认内容与授权补齐规则，不能记录为当前 PR 已获人工批准。 |
| 当前分支有提交，工作区干净 | 取得分支差异，记录确认的基线和 head。 |
| 已绑定 PR，同时本地另有改动 | 审远端 PR head，另列本地额外改动。 |
| 未绑定 PR，本地候选比远端新 | 审本地候选，远端 CI 标明它实际覆盖的版本。 |
| 本地既有暂存也有未暂存内容 | 区分工作区快照与下一次提交的内容，记录审查范围。 |
| 已提交代码导入尚未跟踪的新文件 | 从状态中的 `??` 识别该文件，读取并纳入混合候选审查。 |
| PR 修改 REVIEW.md 或适用的目录规则 | 先加载可信基线规则，把规则修改作为差异审核。 |
| 根 REVIEW.md 未变，候选修改它引用的规则 | 从同一可信提交读取根文件和引用文件，把修改作为差异审核。 |
| 两次查询之间 PR 的 base 或 head 变化 | 用固定 SHA 生成差异，或丢弃按编号取得的差异并重新取证。 |
| GitHub 或 Gitee 只读权限 | 取得可用 PR、检查和讨论证据，缺项明确报告。 |
| 第三轮仍有阻断 | 保留计数，停止自动返修，给有依据的下一步。 |
| 更换审查方法或上下文后继续同一 PR | 沿用已确定的范围、版本与轮次，不能缩成最后一次提交或重置三轮上限。 |
| 配置通过字符串动态加载处理器 | 核对配置、字符串、动态入口与相关调用，不能因直接调用搜索为空就建议删除。 |
| shortcut 局限仍适用，另有被注释掩盖的权限缺陷 | 不重复已接受局限，仍报告有依据的安全问题；注释不能豁免必需要求。 |
| 实际负载已超过 shortcut 中的局限 | 核实具体后果并按项目标准分级；没有重新检查条件通常列为改进建议。 |
| 没有实际负载证据，代码可以更抽象或更短 | 标明未知，不按假想规模要求重构；无实际缺陷或规则依据的精简建议不自动阻断。 |
| 当前环境无法运行，但源码显示可达的缺陷 | 分开报告静态依据、运行状态与待验证疑点，不声称已复现或自动判无问题。 |
| 项目有多项必需检查，返修只新增一个小测试 | 仍满足既有必需检查；测试数量不能作为缩减验证的理由。 |
| 多个调用方因共享解析函数而失败 | 获准后优先修共享根因，核对调用方、测试及配置，保留错误处理和失败断言。 |
| 新提交影响已审核结论 | 重新检查受影响的发现和验证结果，结论绑定新版本。 |
| 需要人工决定 | 显示关键代码、证据、待决定项、对应 PR 和 commit。 |
| 三个 Agent 安装 | 共用一个入口，能调用随包渲染器。 |
| 新旧进度快照 | 都能渲染，报告显示审查目标的证据与链接，并保留检查原记录时间。 |
| 生成或局部更新 HTML | 页首项目名和 Star on GitHub 指向本项目。 |
| 生成 answer-me-with-html 说明页或审查报告 | 检查生成命令、HTML 文件、关键正文、证据和链接，不截图或启动视觉验收。 |
| 被审查产品使用 HTML，验证要求截图 | 驱动实际产品并保留所需截图，可将截图作为证据放入审查报告。 |

验证记录应包括输入、实际执行和覆盖范围。结构与链接检查、场景走查和真实 Agent 执行分别报告。
